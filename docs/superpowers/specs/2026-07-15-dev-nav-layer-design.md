# 設計: 機能仕様書の開発者向けナビ層（AI開発の索引）

- 日付: 2026-07-15
- 対象リポジトリ(ドキュメント): `/home/mhaya/weko-document`
- 対象ディレクトリ: `docs/spec/base`
- 実装リポジトリ(出典): `/home/mhaya/weko`（tag `v2.0.2` で突き合わせ済み）

## 背景 / 目的

`docs/spec/base` 配下の機能仕様書（237ファイル）は、既に実装(tag v2.0.2)と突き合わせ済みで、
各ファイルは「機能 → 関連モジュール → ファイル/メソッド → config/DBスキーマ」まで実装準拠で整備されている。

今回の目的は、この機能仕様書を **WEKO3 開発を行う者への道しるべ** とし、
かつ **AI による開発でも索引として利用できる** ようにすること。

現状の空白:
- `MODULE_01.md` は requirements ファイルへのリンクのみで、**49モジュールが各々何をするかの説明が無い**。
- 各仕様書に「機能 → モジュール」（順引き）はあるが、**「モジュール → 機能」の逆引きが無い**。
- **アーキテクチャ全体像**・**「Xを直すにはどこを見るか」の開発者向け道しるべ**が無い。
- 横断情報（config / DB / endpoint / celery / 権限）は `other/` に個別に存在するが、統合された索引になっていない。

## 方針（確定）

- アプローチ **A: ナビ層の新設**。既存237ファイルの本文は原則変更しない（逆引きリンクの張り先として参照するのみ）。
- 配置は **`spec/base` 直下**（GitBook の同一サイト内。検索対象に含まれる）。
- ソース参照は既存方針を踏襲: **本文にはファイル名・記号名まで（`:行番号`は本文に載せない）**。

## 成果物

### 新規ファイル

1. `spec/base/ARCHITECTURE.md` — システム全体像
   - 技術スタック（Invenio3/Flask、React/AngularJS/jQuery、PostgreSQL/ES/Redis/RabbitMQ/Celery/nginx/Shibboleth/Handle）。出典 `AGENTS.md`・`docker-compose*.yml`
   - Invenio3 のモジュール構造と `entry_points`／Blueprint の考え方
   - リクエストのライフサイクル（Web表示・WebAPI・認証/権限・ES検索・Celery非同期）
   - データの流れ（登録→ワークフロー→インデックス→ES→表示/配布）

2. `spec/base/MODULE_INDEX.md` — モジュール逆引きリファレンス（49モジュール）
   - `invenio-*`／`weko-*` を区分し、各モジュール1行説明＋主要責務
   - 逆引き: そのモジュールを「## 関連モジュール」で参照している機能仕様へのリンク（237ファイルを機械集計して生成）
   - 既存 `other/MODULE_01.md`（ライブラリ一覧）と役割を分け、相互リンク

3. `spec/base/DEV_GUIDE.md` — 開発者向け道しるべ（タスク起点の逆引き）
   - 「こういう変更をしたい → この機能仕様 → このモジュール/エントリポイント」索引
   - 共通エントリポイントの型（`views.py`/Blueprint・`models.py`・`config.py`・`tasks.py`(celery)・`templates`・`static/js`）
   - 開発環境・テスト方法（`install.sh`/docker、`pytest`）。出典 `AGENTS.md`
   - 既知の落とし穴（フロントは別リポジトリ、アイテムタイプはSQL直挿入、陳腐化リンク等。`findings.md` から抽出）
   - AI開発でのこの索引の辿り方

4. `spec/base/CROSS_REFERENCE.md` — 横断索引（ハブ）
   - config キー／DBテーブル／APIエンドポイント／celeryタスク／権限・ロール を、
     既存 `other/CONFIG_01`・`DB_01`・`api/API_ENDPOINT_01`・`other/CELERY_01`・`access_control/README` へ集約リンク＋不足補完

### 更新ファイル

- `SUMMARY.md`: 先頭に「開発者向けガイド」章を追加し上記4本をリンク
- `README.md`: 整備履歴に本ナビ層の追加を1行記載

## 生成方法

- 逆引き（モジュール→機能）は237ファイルの `## 関連モジュール` を機械集計 → 正確性を担保
- モジュール1行説明は各モジュールの `__init__`/docstring と `findings.md` を根拠に作成
- 記述の裏取りは実装 `/home/mhaya/weko` を参照

## 非対象 (YAGNI)

- 237ファイル各々への索引メタ付与（アプローチB）は今回やらない
- 開発観点セクションの各機能への個別追加（アプローチC後半）は今回やらない
- フロントエンド別リポジトリの詳細（検証不可）
