## 実装補足（v2.0.2 実装との突き合わせ）

- 実装補足：スキーマは invenio-db（SQLAlchemy）＋ 各モジュールの Alembic マイグレーションで管理される。テーブル定義の詳細は各モジュールの `models.py` を参照。

- 実装補足（v2.1.0、#61275）：v2.1.0で全モジュールの Alembic 履歴を刷新し、各ブランチ head を単一の新規ベースライン（`upgrade`/`downgrade` が no-op、`down_revision=None`）へ再編した。これは履歴チェーンのリセットであり、テーブル/列の論理内容は変えない。テーブル/列の実体は `postgresql/` の DDL と各 `models.py` が正であり、既存環境への追加変更は `postgresql/update/*.sql` および `tools/update/*.py` で適用する。

- 実装補足（v2.1.0、item_type_mapping）：`item_type_mapping` の `item_type_id` に一意制約 `uq_item_type_mapping_item_type_id` と外部キー `fk_item_type_mapping_item_type_id_item_type`（→ `item_type.id`、ON DELETE CASCADE）を追加し、`mapping` 列に GIN インデックス `idx_mapping_item_type_mapping` を設定した。旧 btree インデックス `idx_created_item_type_mapping`・`idx_item_type_id_item_type_mapping` は削除される。これによりアイテムタイプ1件に対し `item_type_mapping` は常に1行となる（保存は `weko_records.api.Mapping.create_or_update` による upsert）。既存環境の移行は `postgresql/update/W2025-16.sql`、重複行の集約は `tools/update/migrate_item_type_mapping.py` で行う（Alembic 上は `weko_records` の `e0dd9fb514cf` に相当）。
