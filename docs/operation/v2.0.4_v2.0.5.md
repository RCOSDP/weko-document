# WEKO v2.0.4 から v2.0.5 へのアップデート方法

> **注記**: 本手順は、実装の差分(`git diff refs/tags/v2.0.4 origin/develop_v2.0.5`)から作成したものであり、**手順全体を実機では通していない**。
> 確証の持てない手順・判断には **【要確認】** を付けている。【要確認】の箇所は、検証環境で確かめてから本番環境に適用すること。

## docker

本手順は、Docker Compose で構築した単一の WEKO 環境を、v2.0.4 から v2.0.5 へアップデートする場合を対象とする。

JAIRO Cloud 本番環境のような複数機関一括更新、Kubernetes、PgPool、Ingress Controller、fluentd 等のインフラ固有の手順は含まない。

実際の環境によって以下は異なる可能性があるため、適宜読み替えること。

- Docker Compose ファイル名
- Docker Compose のサービス名
- PostgreSQL の DB 名
- `instance.cfg` の環境固有設定
- nginx の `weko.conf` の環境固有設定

以下では Docker Compose ファイルを `docker-compose2.yml` とする。

---

## 0. v2.0.5 での主な変更点(運用に関係するもの)

| 区分 | 内容 | 本手順での対応 |
|---|---|---|
| 認証 | **既定でログインとトークンによる認証を止める設定 `WEKO_PUBLIC_ONLY_MODE` を追加(既定値 `True`)** | 5.1 |
| 設定 | `instance.cfg` にゲスト用トークンの設定を追加(既定値 `False`) | 5.2 |
| 設定 | OAI-PMH の `OAISERVER_RESUMPTION_TOKEN_EXPIRE_TIME` の既定値を 24 時間から 1 時間に変更 | 5.3 |
| 権限 | レコード、ファイル、インデックス、統計、管理機能の判定を見直し | 5.4、13 |
| DB(データ) | `jsonld_mappings` の所属機関名のパスを修正 | 10 |
| サイトマップ | 掲載の判定を見直し。再生成が必要 | 12 |
| DB(スキーマ)、Alembic | 変更なし | — |
| Elasticsearch | マッピング変更なし | — |
| JavaScript / static assets | 変更なし | — |
| nginx、uwsgi、Dockerfile、Compose ファイル | 変更なし | 6、7、8 |

---

## 1. アップデート前の状態を確認する

まず、現在の WEKO のブランチおよびコンテナ状態を確認する。

```bash
cd /path/to/weko

git status
git branch --show-current
git log -1 --oneline
git describe --tags
```

`v2.0.4` であることを確認する。

Docker の状態も確認する。

```bash
docker compose -f docker-compose2.yml ps
```

ローカルに未コミットの変更がある場合は、アップデート作業前にコミットまたは `git stash` 等で退避すること。

### 1.1 ログインとトークンを使う機能を確認する

v2.0.5 は既定でログインとトークンによる認証を止める(5.1)。次のものが止まるので、利用者と連携先に事前に知らせること。

- 画面からのログイン、Shibboleth、外部サービスによるログイン
- OAuth2 トークン、Personal Access Token を使う API、SWORD
- ワンタイム URL、シークレット URL、ゲスト用 URL
- サイトライセンスによるファイルの取得

---

## 2. バックアップを取得する

アップデート前に、少なくとも PostgreSQL と WEKO 設定ファイルをバックアップする。

### 2.1 PostgreSQL

```bash
docker compose -f docker-compose2.yml exec -T postgresql \
  pg_dump -U invenio invenio \
  > weko_v2.0.4_before_upgrade.sql
```

バックアップファイルが作成されていることを確認する。

```bash
ls -lh weko_v2.0.4_before_upgrade.sql
```

環境によって DB 名が `invenio` ではない場合は読み替えること。

### 2.2 設定ファイル

以下のような環境固有設定をバックアップする。

```bash
mkdir -p backup_v2.0.4

cp .env backup_v2.0.4/ 2>/dev/null || true
cp docker-compose2.yml backup_v2.0.4/
cp scripts/instance.cfg backup_v2.0.4/ 2>/dev/null || true
cp nginx/weko.conf backup_v2.0.4/ 2>/dev/null || true
cp uwsgi.ini backup_v2.0.4/ 2>/dev/null || true
```

## 3. WEKO を停止する

データベースの更新中にデータ更新や外部からのアクセスが発生しないよう、WEKO Web、Celery worker、nginx を停止する。

```bash
docker compose -f docker-compose2.yml stop nginx web worker
```

---

## 4. WEKO v2.0.5 のソースコードへ更新する

最新のブランチ・タグ情報を取得する。

```bash
git fetch --all --tags
```

`v2.0.5` タグが作成されている場合はタグを使用する。

```bash
git checkout v2.0.5
```

本書作成時点では `v2.0.5` タグは作成されていない。タグが無い場合は開発ブランチを使用する。

```bash
git checkout develop_v2.0.5
git pull
```

更新後、対象を確認する。

```bash
git branch --show-current
git log -1 --oneline
```

## 5. instance.cfg を確認する

`scripts/instance.cfg` を確認し、環境固有の変更を維持したまま、以下を反映する。

### 5.1 WEKO_PUBLIC_ONLY_MODE

| 設定キー | 既定値 | 内容 |
|---|---|---|
| `WEKO_PUBLIC_ONLY_MODE` | `True` | ログインとトークンによる認証を止め、公開ページだけを動かす |

**v2.0.5 は `True` のまま運用する。** `instance.cfg` と環境変数 `INVENIO_WEKO_PUBLIC_ONLY_MODE` に `False` が残っていないことを確認する。

```bash
grep -n 'WEKO_PUBLIC_ONLY_MODE' scripts/instance.cfg
docker compose -f docker-compose2.yml config | grep -n 'WEKO_PUBLIC_ONLY_MODE'
```

どちらも何も表示されなければよい。

値は起動時に読むので、変更するには再起動が必要である。

### 5.2 ゲスト用トークン

v2.0.5 の `scripts/instance.cfg` に次の設定が追加された。環境固有の `instance.cfg` を使用している場合は同じ設定を追加する。

```python
#--- Enable issuing tokens for guest activities
WEKO_WORKFLOW_GUEST_TOKEN_ISSUE_ENABLED = False
#--- Enable accepting tokens for guest activities
WEKO_WORKFLOW_GUEST_TOKEN_ACCEPT_ENABLED = False
```

`WEKO_PUBLIC_ONLY_MODE = True` のときは、これらを `True` にしてもトークンは発行も受け入れもされない。

### 5.3 OAI-PMH の resumptionToken と scroll の有効期限

| 設定キー | v2.0.4 | v2.0.5 | 内容 |
|---|---|---|---|
| `OAISERVER_RESUMPTION_TOKEN_EXPIRE_TIME` | `86400`(24 時間) | `3600`(1 時間) | resumptionToken の有効期限。Elasticsearch の scroll の keep-alive にも使う |

次の点を確認する。

- ハーベスタが、次のページを取りに来るまでの間隔が 1 時間を超えないこと。超える場合は `instance.cfg` で値を上書きする。
- Elasticsearch の `search.max_keep_alive` を 3600 秒より短く設定している場合は、この値以上にする。短いままだと、OAI-PMH の `ListRecords`、`ListIdentifiers` が失敗する。

### 5.4 権限の設定を上書きしている場合

`instance.cfg` で `RECORDS_REST_ENDPOINTS`、`RECORDS_UI_ENDPOINTS` の権限に関する設定を上書きしている場合は、v2.0.5 の既定値との差分を確認する。v2.0.5 では、これらの既定値に権限の確認が追加されている。

## 6. nginx の設定を確認する

v2.0.4 から v2.0.5 の差分に `nginx/` の変更はない。環境固有の設定を変更している場合は、ソース更新後も維持されていることを確認する。

## 7. uwsgi.ini を確認する

v2.0.4 から v2.0.5 の差分に `uwsgi.ini` の変更はない。

---

## 8. Docker イメージを更新する

Python のコードが変更されているので、WEKO の Docker image を再ビルドする。

```bash
docker compose -f docker-compose2.yml build
```

キャッシュを使用しない場合:

```bash
docker compose -f docker-compose2.yml build --no-cache
```

Registry 上の image を利用している場合は、Compose ファイル内の image tag を v2.0.5 用に変更後、以下を実行する。

```bash
docker compose -f docker-compose2.yml pull
```

確認:

```bash
docker compose -f docker-compose2.yml images
```

## 9. PostgreSQL を起動する

停止している場合は PostgreSQL を起動する。

```bash
docker compose -f docker-compose2.yml up -d postgresql
```

確認:

```bash
docker compose -f docker-compose2.yml ps
```

## 10. データベースを更新する

v2.0.5 では DB のスキーマに変更はない。既存の環境では、`jsonld_mappings` の所属機関名のパスだけを修正する。

新規の環境向けの `postgresql/ddl/W2025-29.sql` と `scripts/demo/item_type.sql` は修正済みだが、既存の環境には反映されない。

対象の行を確認する。

```bash
docker compose -f docker-compose2.yml exec postgresql \
  psql -U invenio invenio -c "
SELECT id, name FROM jsonld_mappings
 WHERE mapping::text LIKE '%jpcoar:affiliationjpcoar:affiliationName%';"
```

修正する。

```bash
docker compose -f docker-compose2.yml exec postgresql \
  psql -U invenio invenio -c "
UPDATE jsonld_mappings
   SET mapping = replace(mapping::text,
         'jpcoar:affiliationjpcoar:affiliationName',
         'jpcoar:affiliation.jpcoar:affiliationName')::jsonb
 WHERE mapping::text LIKE '%jpcoar:affiliationjpcoar:affiliationName%';"
```

上の確認の SQL を再度実行し、0 件になることを確認する。

環境でマッピングを編集している場合は、修正後の内容を確認すること。

## 11. WEKO v2.0.5 を起動する

全体を起動する。

```bash
docker compose -f docker-compose2.yml up -d
```

状態を確認する。

```bash
docker compose -f docker-compose2.yml ps
```

Web、worker、nginx のログを確認する。

```bash
docker compose -f docker-compose2.yml logs --tail=200 web
docker compose -f docker-compose2.yml logs --tail=200 worker
docker compose -f docker-compose2.yml logs --tail=200 nginx
```

起動時に traceback や設定エラーが発生していないことを確認する。

## 12. サイトマップを再生成する

v2.0.5 ではサイトマップの掲載の判定を見直した。再生成するまで、前の内容が残る。

```bash
docker compose -f docker-compose2.yml exec web \
  celery -A invenio_app.celery call weko_sitemap.tasks.update_sitemap
```

Celery worker が v2.0.5 で動いていることを先に確認する。結果は保存されないので、完了はサイトマップを取得して確認する。

```bash
curl -k -s https://<host>/weko/sitemaps/sitemapindex.xml
```

ログインできないので、管理画面からは再生成できない。

---

## 13. 動作確認を行う

アップデート後、最低限以下を確認する。

### トップページ

- WEKO トップページが正常に表示される
- HTTP 500 / 502 が発生しない

### 検索

- 既存アイテムを未ログインで検索できる
- 検索結果件数に不自然な差異がない

### アイテム詳細

- 公開アイテムの詳細画面が表示できる
- メタデータが正常に表示される
- 公開ファイルがダウンロードできる

### 公開していないもの

- 非公開アイテムの詳細画面が表示されない

### 認証の停止

- `/login/` へ正しいメールアドレス・パスワードを POST すると 403 になる
- `/oauth/token` が 403 になる
- 有効なアクセストークンを付けた API が 401 になる

```bash
curl -k -s -o /dev/null -w '%{http_code}\n' -X POST https://<host>/oauth/token
```

### OAI-PMH

- `verb=Identify` と `verb=ListRecords` が応答する
- `resumptionToken` で 2 ページ目を取得できる

```bash
curl -k -s 'https://<host>/oai?verb=Identify'
curl -k -s 'https://<host>/oai?verb=ListRecords&metadataPrefix=oai_dc'
```

### サイトマップ

- `sitemapindex.xml` と各ページが取得できる
- 公開アイテムの URL が含まれ、非公開アイテムの URL が含まれない

## 16. 切り戻し

アップデートに失敗した場合は、v2.0.4 のソースと 2 で取得したバックアップに戻す。

WEKO を停止する。

```bash
docker compose -f docker-compose2.yml stop nginx web worker
```

ソースを v2.0.4 に戻す。

```bash
git checkout v2.0.4
```

2.2 で退避した設定ファイルを必要に応じて戻し、イメージを再ビルドする。

```bash
docker compose -f docker-compose2.yml build
```

10 の修正は v2.0.4 でも問題にならないので、DB は通常は戻さなくてよい【要確認】。戻す場合は 2.1 のダンプを投入する。

起動し、サイトマップを再生成する。

```bash
docker compose -f docker-compose2.yml up -d
docker compose -f docker-compose2.yml exec web \
  celery -A invenio_app.celery call weko_sitemap.tasks.update_sitemap
```

# アップデート処理の流れ

```text
事前確認(ログインとトークンを使う機能の周知)
    ↓
バックアップ(PostgreSQL、instance.cfg、nginx 設定)
    ↓
WEKO 停止(nginx / web / worker)
    ↓
WEKO v2.0.5 ソースコード更新
    ↓
instance.cfg 確認(WEKO_PUBLIC_ONLY_MODE、ゲスト用トークン、OAI-PMH の有効期限)
    ↓
Docker image 更新
    ↓
PostgreSQL 起動
    ↓
jsonld_mappings の修正
    ↓
WEKO v2.0.5 起動
    ↓
サイトマップ再生成
    ↓
動作確認
```
