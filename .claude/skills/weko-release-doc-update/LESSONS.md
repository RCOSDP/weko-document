# v2.1.0 のドキュメント更新で得た注意点

## 判定・内容
- **「今回の変更」は直前のリリースタグとの差分で決める。** 前回突合地点（b19e39d8a）との差分には v2.0.3／v2.0.4 でリリース済みの変更（issue62569 の一部、S3 読み取り専用キー、502 対策ブランチ名の誤解）が混ざっていた。`git merge-base --is-ancestor <commit> <PREV_TAG>` で確認する。
- **ブランチ名を信じない。** 「release_v2.0.3(Measures against 502 errors)」から取り込まれた 502 対策キャッシュは、実際には v2.0.3／v2.0.4 のタグに含まれておらず v2.1.0 の変更だった。
- **画面ラベルは実際の表示が正。** 翻訳ファイルから「説明」と直したラベルが、実画面では「記述」だった。fuzzy の訳（"Active"→"Save"）は .mo に入らない。迷ったら撮影して確認する。
- **未マージの実装 PR を前提に書いた箇所は記録する。** PR の内容が変わったら戻す必要がある（v2.1.0 では nginx の login.py 復元 PR #1936、ウィジェット画像の PR #1937）。
- **別エージェントの結論が食い違ったらソースで決着させる**（例：SWORD PUT の recid 補完は「未実装」報告が誤りで、`handle_check_exist_record` が `request.view_args` から補完していた）。
- **リリース前に実装の重大不具合が見つかることがある**（v2.1.0：nginx Dockerfile が arm64 版で上書きされ login.py が消失、ウィジェット画像が未ログインで 401）。ドキュメントで誤魔化さず、実装に PR を出す。
- **v2.0.4 では動かないが v2.1.0 で直っている不具合**（削除ボタン issue62807）のように、リリースごとの状態差も確認する。

## 編集の進め方
- **並列エージェントに同じファイルを同時編集させない。** 大きいマニュアルは章境界で分割→編集→`cat` で結合（分割直後に `cmp` で一致確認）。英語版の新規節は「断片ファイル＋差し込み指示（INSERT_BEFORE／INSERT_AFTER_SECTION）」で作り、取りまとめ役が `insert_frags.py` で一括差し込み。直接編集担当と断片担当の内容が重なることがあるので、差し込み前に重複を除く。
- **見出しの文字列を変えない。** 見出しにタグや文言を足すとアンカーが変わり、目次・他ファイル・ガイド間のリンクが切れる（タグは本文にだけ付ける）。
- **英語版の目次番号は断片作成時の前提がばらつく。** 下から差し込むと元の番号基準で整合するが、担当が「差し込み後」の番号を書いてくることがあるので、差し込み後に必ず連番チェックして直す。
- **章が増えたら表・図番号と章構成の一覧も直す。** 本文の「Table N-M」は章ごとに振り直し、他マニュアルからの参照（User manual の Table 5-2 等）は変えない。キャプションが `> ` 付きの引用で書かれていることがあるので検出漏れに注意。
- **表・図番号の確認は caption_check.py で行う。** キャプションは `> ` 付き、画像の直後、Word のファイル名の名残（`zu0824070.tif`）の直後にも書かれている。v2.1.0 では検出漏れのせいで飛びに見えていたほか、実際の誤りとして「Figure 5.‑10」「Table 15.‑12」（第 16 章の中）、同じ番号の重複（USER の Figure 5-23）があった。番号を直したら、本文の「See "Figure N-M. …"」の参照もタイトルで確かめて直す。
- **Word 変換の名残** として、節をまたいだ通し番号の手順（「335.」）、旧通し番号での小見出し参照（「(5) ファイルを設定する」）、`ANCHORID=…【参照元】…【E】` が残っている。突合のついでに直す。
- **Word の図・アイコンのファイル名（`zu0824070.tif`、`icon030010.tif`、`msg040010.tif`）が本文に文字として残っていた**（図番号・画像の前後、表のセル。v2.1.0 で日本語版 ADMIN 36・英語版 ADMIN 334・USER 221 か所を除去）。`(?:zu|icon|msg)[A-Za-z0-9_]*\.tif` で除き、それだけの行は削除する。英語版の `\<TBLATT POSITION=… \>`（表の属性。引用符が全角 `”` のものもある）も同じ種類の名残で、`\\<TBLATT[^>]*\\>` で除いた（ADMIN 43・USER 41 か所。除去前後で HTML の表の数が変わらないことを確認）。
- **作業記録はリポジトリに入れない**（findings・計画・進捗・変更点一覧・設計メモ）。`.gitignore` 済み。

## スクリーンショット
- 座標で注記を移植するのではなく、画面の部品を特定して注記を描き直す（`annotate.js`）。番号は本文の表の現在の項番。
- 英語版は画像番号が違うので、まず節単位で日本語版との対応表を作る。日本語版33枚のうち英語版に対応があったのは16枚だった。
- 英語画面の検索0件は言語別のインデックスツリーキャッシュが原因だった。アクティビティのロックは Force Unlock で解除できる（詳細は rules/SCREENSHOT_RULES.md）。
- 撮影で画面を開くと、翻訳漏れ（英語画面の「セイ」「メイ」、「【非推奨】」、`oa_policy_export`、「Strage Location」等）が見つかる。実装側への報告事項として残す。
- ユーザーの了承があっても、サブエージェントの環境変更は権限判定で止まることがある。止まったら取りまとめ役が実行する（エージェントに回避させない）。

## 検証（コミット前に毎回）
- 見出し文字列が変わっていない（新規追加のみ）／タグ数が意図どおり／タグ以外の本文が変わっていない（タグ付け時）
- 目次：新規項目のリンク先が実在し、番号が飛び・重複なく連続
- 本文の節番号参照が目次と一致、表・図番号が章内で連番
- CRLF のファイル（GUIDE の一部）の改行を保つ
- push 前に `git fetch` してリモートの変更をマージ
- honkit でビルドし、分岐点からの新しいリンク切れが無いこと（`scripts/build_docs.sh --compare <DOC_BASE>`）

## ビルド（honkit）
- **公開されるのは HTML 版。** ビルド結果は別リポジトリに登録して github.io（https://rcosdp.github.io/weko/user/ など）で公開している。GitHub 上の markdown で効くリンクでも、HTML 版で切れれば公開サイトで切れる。
- 英語版（`manuals_en`）は 1 ファイルの本なので、`book.json` の `structure.readme` でそのファイルを README 扱いにし、空の `SUMMARY.md` を置いてビルドする（v2.1.0 で追加）。
- **英語版の見出しには Word のフィールドコード（`LINKID=…【参照先】`、`\<INDEXWORD PRONOUNCE=… \>`）が文字として残っていた。** honkit は `\<INDEXWORD…\>` をタグとして扱うので、フィールドコード入りの GitHub 式アンカーは HTML 版で切れ、見出しにもフィールドコードが表示される。v2.1.0 では `scripts/strip_heading_fieldcodes.py` で見出しから除去し（ADMIN 166・USER 47 見出し）、旧アンカーへのリンク（約 200）を新しいアンカーに書き換えた。その後ビルドして、同名見出し（`#register-items-1` など）だけ `add_anchors.py` で `<a id>` を補った。本文中のフィールドコード（`ANCHORID=…【参照元】…【E】`、本文・表の INDEXWORD（表の中は `&lt;INDEXWORD…&gt;`）、キャプションの LINKID）も、リンクには関係しないので正規表現で一括除去した（ADMIN 163・USER 110 行。中身が空になった行は削除）。除去前後で「フィールドコードと空行を除けば同一」であることを確かめる。
- 英語版の章見出しは空の `#` の次の行に章名があった（`#   ` / `Author Management`）。v2.1.0 で `# Author Management` の 1 行にまとめた。番号付きリストの中に入った見出しは、`1.  ### …` のように同じ行にあれば両方で見出しになるが、ずれて見出しにならないものはリスト記号を外す。
- **見出しの先頭に見えない文字（U+200F など）が入っていることがある。** GitHub はアンカーから除くが honkit は残すので切れる（ADMIN の「Index Tree」など 3 見出し）。見出しから削除する。
- **arm64 では `npm install` が puppeteer の Chromium ダウンロードで失敗する。** `PUPPETEER_SKIP_DOWNLOAD=true PUPPETEER_SKIP_CHROMIUM_DOWNLOAD=true` を付ける。`npm install` は `package-lock.json` を書き換えるので `npm ci` を使う（`build_docs.sh` が実施）。
- **ログのノイズは失敗ではない。** shelljs の circular dependency 警告、`prismjs/components/prism-Python.js` の MODULE_NOT_FOUND（コードブロックの言語名 `Python` が大文字）、deprecated 警告、spec の「search index is too big」が出ても、最後に「generation finished with success」があれば成功。
- **honkit と GitHub はアンカーの作り方が違う。** honkit は全角の括弧・コロン・中黒を残し、`_` を消し、同名見出しに `-1` を付けない。GitHub 式のアンカー（`#認証認可の共通事項release_v210`、`#アイテムを一括出力する-1`）は GitHub では効くが honkit のサイトでは切れる（check_build.py の SLUG）。見出しは変えずに、`scripts/add_anchors.py` で見出しの直前に `<a id="GitHub式アンカー"></a>` を入れれば両方で効く（v2.1.0 で 54 か所）。リンクは GitHub 式で書く。
- **見出しに `\<version>` を書くと honkit では HTML タグとして扱われ**、見出しが「GET /api/\」と崩れてアンカーからも消える（v2.1.0 の spec/access_control・api で 53 見出し・83 リンク）。見出しのパス引数はバッククォートで囲む（`` GET `/api/<version>/authors` `` は honkit も GitHub と同じ `get-apiversionauthors` になる）。`<pid_value>` のように `_` を含むものは add_anchors.py で補う。
- v2.1.0 では分岐点時点で既に切れていたリンクも直した。多くは Word 変換の名残で、
  - 別の仕様書への参照が同じページ内のアンカー（`[USER-2-4: アイテム一括出力](#アイテム一括出力)`）や `(\\l)` になっている → ラベルの仕様書 ID を SUMMARY.md で引いてファイルへのリンクにする。
  - 画像が `media/media/imageN.png`（仕様書のサブフォルダからの相対）になっている → 実体は `spec/base/media/media/`。番号が他の文書と重なることがあるので、中身を見て文脈と合うことを確かめてから `../` を足す。
  - GUIDE の `sword_setting_5/6.png` はどのブランチにも無かった → ローカル環境で撮り直した（マッピング選択だけで ✓／✘ が出るので環境の変更は不要）。
- **段落の途中の `<!-- -->` は honkit では隠れず、そのまま文字として表示される**（ADMIN の目次に `<!--` と古い `_Toc…` リンクが出ていた）。不要な行はコメントにせず削除する。
