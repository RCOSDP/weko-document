# v2.1.0 のドキュメント更新で得た注意点

## 判定・内容
- **「今回の変更」は直前のリリースタグとの差分で決める。** 前回突合地点（b19e39d8a）との差分には v2.0.3／v2.0.4 でリリース済みの変更（issue62569 の一部、S3 読み取り専用キー、502 対策ブランチ名の誤解）が混ざっていた。`git merge-base --is-ancestor <commit> <PREV_TAG>` で確認する。
- **ブランチ名を信じない。** 「release_v2.0.3(Measures against 502 errors)」から取り込まれた 502 対策キャッシュは、実際には v2.0.3／v2.0.4 のタグに含まれておらず v2.1.0 の変更だった。
- **画面ラベルは実際の表示が正。** 翻訳ファイルから「説明」と直したラベルが、実画面では「記述」だった。fuzzy の訳（"Active"→"Save"）は .mo に入らない。迷ったら撮影して確認する。
- **未マージの実装 PR を前提に書いた箇所は記録する。** PR の内容が変わったら戻す必要がある（v2.1.0 では nginx の login.py 復元 PR #1936、ウィジェット画像の PR #1937）。
- **別エージェントの結論が食い違ったらソースで決着させる**（例：SWORD PUT の recid 補完は「未実装」報告が誤りで、`handle_check_exist_record` が `request.view_args` から補完していた）。
- **リリース前に実装の重大不具合が見つかることがある**（v2.1.0：nginx Dockerfile が arm64 版で上書きされ login.py が消失、ウィジェット画像が未ログインで 401）。ドキュメントで誤魔化さず、実装に PR を出す。
- **v2.0.4 では動かないが v2.1.0 で直っている不具合**（削除ボタン issue62807）のように、リリースごとの状態差も確認する。

## 編集の進め方
- **並列エージェントに同じファイルを同時編集させない。** 大きいマニュアルは章境界で分割→編集→`cat` で結合（分割直後に `cmp` で一致確認）。英語版の新規節は「断片ファイル＋差し込み指示（INSERT_BEFORE／INSERT_AFTER_SECTION）」で作り、取りまとめ役が `insert_frags.py` で一括差し込み。直接編集担当と断片担当の内容が重なることがあるので、差し込み前に重複を除く。
- **見出しの文字列を変えない。** 見出しにタグや文言を足すとアンカーが変わり、目次・他ファイル・ガイド間のリンクが切れる（タグは本文にだけ付ける）。
- **英語版の目次番号は断片作成時の前提がばらつく。** 下から差し込むと元の番号基準で整合するが、担当が「差し込み後」の番号を書いてくることがあるので、差し込み後に必ず連番チェックして直す。
- **章が増えたら表・図番号と章構成の一覧も直す。** 本文の「Table N-M」は章ごとに振り直し、他マニュアルからの参照（User manual の Table 5-2 等）は変えない。キャプションが `> ` 付きの引用で書かれていることがあるので検出漏れに注意。
- **Word 変換の名残** として、節をまたいだ通し番号の手順（「335.」）、旧通し番号での小見出し参照（「(5) ファイルを設定する」）、`ANCHORID=…【参照元】…【E】` が残っている。突合のついでに直す。
- **作業記録はリポジトリに入れない**（findings・計画・進捗・変更点一覧・設計メモ）。`.gitignore` 済み。

## 検証（コミット前に毎回）
- 見出し文字列が変わっていない（新規追加のみ）／タグ数が意図どおり／タグ以外の本文が変わっていない（タグ付け時）
- 目次：新規項目のリンク先が実在し、番号が飛び・重複なく連続
- 本文の節番号参照が目次と一致、表・図番号が章内で連番
- CRLF のファイル（GUIDE の一部）の改行を保つ
- push 前に `git fetch` してリモートの変更をマージ
