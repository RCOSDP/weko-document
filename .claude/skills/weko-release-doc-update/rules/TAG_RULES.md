# 【{{NEW_VER}}】タグ付けルール

## 目的
weko-document（/home/mhaya/weko-document, branch develop_{{NEW_VER}}）で、main から分岐した時点（commit **{{DOC_BASE}}**）以降に変更された記述のうち、
**WEKO の {{NEW_VER}} で実装の挙動が変わったことによる記述**に「【{{NEW_VER}}】」タグを付け、読者が {{NEW_VER}} での変更点を見分けられるようにする。

## 差分の取り方（ドキュメント側）
- `git -C /home/mhaya/weko-document diff {{DOC_BASE}} HEAD -- <ファイル>` で、担当ファイルの変更箇所を確認する（追加行 `+` が対象候補）。
- 分割チャンクを担当する場合も、元ファイル全体の差分から自分のチャンクに該当する部分を探すこと。

## タグを付けるかの判定（最重要）
実装リポジトリ `{{IMPL_REPO}}`（読み取り専用。checkout 等の状態変更は禁止。`git -C {{IMPL_REPO}} log|show|diff` のみ可）で、
**`{{PREV_TAG}}`（直前のリリース）と `origin/{{RELEASE_REF_NAME}}`（今回のリリース）の差分によって挙動・画面・設定・API が変わった事柄**にだけタグを付ける。

- タグを付ける例：{{NEW_VER}} の新機能・新画面項目・新設定キー・新 API、権限や挙動の変更、廃止された機能（{{PREV_VER}} では違っていたもの）
- タグを付けない例：
  - {{PREV_VER}} 以前から同じ挙動なのに、ドキュメントの記述が誤っていた・不足していたのを直したもの（誤記訂正、旧ラベルの修正、既存機能の書き漏れの追記）
  - **{{PREV_VER}} 以前で既にリリース済みの変更**（前回突合地点 {{LAST_AUDIT}} が {{PREV_TAG}} より古い場合、その間のパッチリリースの変更が混ざる。v2.1.0 では v2.0.4 に入っていた issue62569 の一部や S3 読み取り専用キーを誤って新機能扱いしかけた）。迷ったら `git -C {{IMPL_REPO}} merge-base --is-ancestor <commit> {{PREV_TAG}}` で確認する
  - 「未リリース（リリース見送り）」の注記
  - 文体・書式の整理、目次・改定履歴・更新履歴の行
- 未マージの PR を前提にドキュメントを書いている場合は、その PR を含めた挙動で判定し、前提にした PR を取りまとめ役に報告する。
- 判断の根拠は実装の差分で確認すること（`git -C {{IMPL_REPO}} diff {{PREV_TAG}} origin/{{RELEASE_REF_NAME}} -- modules/<module>`、`git -C {{IMPL_REPO}} log {{PREV_TAG}}..origin/{{RELEASE_REF_NAME}} -- <path>`）。参考：取りまとめ役の作業メモ（findings 等）。

## タグの表記
- 日本語文書：`【{{NEW_VER}}】`
- 英語版マニュアル：`[{{NEW_VER}}]`

## 付け方（変更箇所に付ける。見出しには付けない）
**【方針変更】見出し（# 〜 ####）にはタグを付けない。** 見出しの文字列が変わるとアンカー（リンク先）が変わってしまうため。既に見出しに付けたタグがあれば取り除くこと。

1. **変更箇所**：タグ対象の変更・追加にあたる段落、箇条書きの項目、表の行の先頭に付ける。
   - Markdown の表：その行の最初のセルの先頭に付ける。
   - HTML の表（`<td>`）：その行の最初の `<td>`（中に `<p>` があれば最初の `<p>`）のテキストの先頭に付ける。
   - 番号付き手順の項目：項目の本文の先頭に付ける。
   - コードブロックの中には付けない（直前の説明文に付ける）。
   - 画像の行（`![...]`）には付けない。
2. **節やページがまるごと {{NEW_VER}} の新規**の場合は、その節の**最初の本文段落の先頭にだけ**付け、中の段落ごとには付けない（見出しには付けない）。
3. 削除された記述にはタグを付けられない。{{NEW_VER}} で機能が廃止されたことを読者が知る必要がある場合に限り、「【{{NEW_VER}}】〜は廃止されました。」のような短い一文を該当箇所に加えてよい。
4. 目次（`## 目次` や Table of Contents）、改定履歴・更新履歴の表、SUMMARY.md は編集しない。
5. タグ以外の本文は変更しない。

## 作業方法
- 担当ファイル（またはチャンク）だけを Edit ツールで編集する。コミットはしない。
- 改行コード（CRLF のファイルは CRLF のまま）を保つ。

## 最終報告（40行以内、日本語）
1. タグを付けた箇所の一覧（見出し名と、付けた変更箇所の要約。根拠となる実装のコミットまたは差分の要点）
2. 差分にはあるがタグを付けなかった主な変更（記述訂正・{{PREV_VER}} 以前からの挙動など）の要約と件数
3. 判断に迷ったもの
