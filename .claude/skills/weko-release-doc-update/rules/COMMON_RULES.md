## 記述ルール
- 担当外のファイルは編集しない。編集は Edit ツールで行う（大規模置換が必要なら Write も可だが、担当ファイルのみ）。
- 「実装準拠に書き換え」が原則。推測で書かない。ソースで確認できない事項（例：別リポジトリ weko-frontend の AMS 画面の細部）は無理に書き換えず、報告に「未検証」として挙げる。
- 既定で無効な config に依存する挙動は「〜を有効にしている場合」と条件付きで書く。
- コミット・push はしない（取りまとめ役が行う）。

### マニュアル（docs/manuals 配下・分割チャンク）の場合
- 利用者・管理者向け文書。既存の文体（です・ます調、番号付き手順、表）と書式（HTML表の箇所はHTML表のまま）に合わせる。
- 本文にソースファイル名・関数名・モジュール名は書かない。設定ファイル（instance.cfg 等）で設定が必要な config キーは、既存記述の流儀に合わせて記載可。
- 画面ラベルは実際の画面表示に合わせる（テンプレートと翻訳ファイル ja messages.po で確認。翻訳ファイルと画面表示が違う場合があるので、可能ならスクリーンショットで確認する）。
- 画像（スクリーンショット）は作成・差し替えできない。画面が変わって画像が古いと思われる箇所は本文は直し、報告の「画像差し替え要」に挙げる。
- 既存の見出しの文字列は変更しない（アンカーが変わりリンクが切れる）。新しい見出しを追加した場合は報告に列挙する（目次は取りまとめ役が更新する）。目次（## 目次 セクション）は編集しない。
- 表番号・図番号は、追加により後続番号のずれが生じる場合でも、担当チャンク内で整合が取れる範囲で直す。

### 機能仕様書（docs/spec/base 配下）の場合
- 既存の書式・粒度に合わせる。本文にはモジュール／ファイル名／クラス・メソッド名／config キー／テーブル名まで書いてよいが、行番号は書かない。
- 変更点は既存の該当箇所を直接書き換える（矛盾は実装準拠に修正）。補足は既存の「> 実装補足（{{NEW_VER}}）：」ブロックの流儀で追記してよい。
- 変更したファイルの末尾「更新履歴」表に1行追加: `| {{DATE}} | {{RELEASE_COMMIT}} | {{RELEASE_REF_NAME}}突合：<変更概要> |`
- 新規ファイルを作る場合は docs/spec/base/SUMMARY.md と該当カテゴリ README.md への追加も担当範囲に含む（SUMMARY.md は複数担当が触る可能性があるため、追加行のみを最小限の Edit で）。
